# CLAUDE.md — project conventions

White-label client portal for grant consultants. One Cloudflare Worker (static SPA + API), one consultancy per deployment, deployed with the Deploy to Cloudflare button.

**Sources of truth**
- Product and security: `docs/SPEC.md`. If a request disagrees with the spec, the spec wins; flag the conflict.
- Visual design: `docs/design/` (`Design.html` is the original bundle; `boards/*.html` are the extracted, readable boards). Tokens, component CSS, the accent-ramp algorithm, and the three sample brands live in `boards/01-foundations.html`.
- Decisions made where the spec is silent: `docs/DECISIONS.md`. Milestone checklist: `docs/PLAN.md` (keep it updated).

## Non-negotiables (short form)
1. **Deploy button works from a fresh fork** with only `RESEND_API_KEY` pasted. Bindings have no account IDs; secrets are listed in `.dev.vars.example` (max 3, spec §3.2); binding help text lives in `package.json → cloudflare.bindings`; `deploy` = `npm run db:migrate && wrangler deploy`; migrations reference binding `DB`; **build must pass with an empty env**.
2. **One consultancy per deploy.** No multi-tenant code paths, but keep the `orgs` table / `org_id` columns.
3. **Zero maintainer branding** in any client-facing surface, email, PDF, favicon, manifest, or title. The product name (`grant-portal`) appears only in README/repo metadata/infra names. `tests/branding.test.ts` greps the built client bundle and email templates.
4. **Security per spec §7** is a requirement. Every route gets authz in middleware and an IDOR test.
5. **OpenGrants is optional.** App fully works without `OPENGRANTS_API_KEY`. Never invent endpoints — the client is generated from the committed OpenAPI spec (`worker/integrations/opengrants/openapi.json`).
6. **No invented facts.** No hardcoded OpenGrants pricing, counts, or marketing copy. Request limit is config (default 25/day).

## Stack (spec §4 — don't substitute without asking)
Workers + `nodejs_compat` · Hono · Zod · Drizzle ORM + D1 · R2 · KV · Queues · Cron · Turnstile · React + Vite (`@cloudflare/vite-plugin`) · TanStack Router (file routes) + Query · Tailwind v4 (semantic CSS-variable tokens only) · Radix · Lucide · react-email + Resend behind `EmailProvider` · SimpleWebAuthn · Vitest + `@cloudflare/vitest-plugin` · Playwright · TypeScript strict · **npm** (commit `package-lock.json`).

Pinned: TypeScript 6.0.x (typescript-eslint doesn't support 7 yet), Vitest 4.1.x (`@cloudflare/vitest-plugin` peer; it replaced `@cloudflare/vitest-pool-workers`, see DECISIONS D-011).

## Layout (spec §4.3)
```
worker/
  index.ts            Hono app + fetch/scheduled/queue exports
  env.ts              Env type (bindings, vars, secrets)
  lib/                ids (ULID), crypto, http helpers, security headers
  auth/               magic links, sessions, passkeys, CSRF
  api/                route modules per domain
  jobs/               queue consumer, cron dispatch
  email/              EmailProvider interface, resend.ts, templates/
  integrations/opengrants/
  db/schema.ts        Drizzle schema (source of truth for migrations)
migrations/           D1 SQL migrations (generated by drizzle-kit; add-only)
app/                  React SPA
  routes/             TanStack file routes (workspace/*, portal/*, auth/*)
  ui/                 themed components (semantic tokens only)
  lib/                api client, query setup
tests/
  worker/             Vitest (runs inside workerd)
  unit/               Vitest (pure functions)
  e2e/                Playwright
docs/                 SPEC, PLAN, DECISIONS, design, deploy/security/theming/opengrants guides
scripts/              build/release helpers (never shipped to clients)
```

## Commands
| Command | What |
|---|---|
| `npm run dev` | Vite + Worker together with local D1/R2/KV (applies local migrations first) |
| `npm run build` | `vite build` → `dist/` (must pass with no secrets) |
| `npm run typecheck` | `tsc -b` across app, worker, tests |
| `npm run lint` | ESLint |
| `npm test` | Vitest (worker pool + unit) |
| `npm run test:e2e` | Playwright against `vite preview` |
| `npm run db:generate` | drizzle-kit generate from `worker/db/schema.ts` |
| `npm run db:migrate:local` | apply migrations to local D1 |
| `npm run db:migrate` | apply migrations to remote D1 (`DB` binding) — used by `deploy` |
| `npm run cf-typegen` | regenerate `worker-configuration.d.ts` |

## Conventions
- IDs are ULIDs (`worker/lib/ids.ts`); timestamps are UTC epoch ms integers.
- Schema changes: edit `worker/db/schema.ts`, run `npm run db:generate`, commit the SQL. **Migrations only add** (no drops/renames without a two-release deprecation).
- Every API route: Zod-validated input, authz enforced by middleware (scope by org + role + client membership), never by the handler alone.
- No hardcoded colors in components — only semantic tokens (`bg`, `raised`, `sunken`, `text`, `text2`, `acc-solid`, …; see `app/styles/tokens.css`).
- No `innerHTML`/`dangerouslySetInnerHTML` except through the server-side sanitizer output.
- Secrets never reach the client bundle; nothing in `vite build` may read a secret.
- Prefer small, boring, tested code. New dependency → needs a reason and goes in the milestone report.
- Pick the most secure reasonable default when the spec is silent; record it in `docs/DECISIONS.md`.

## Testing rules
- Worker/API tests run in workerd via `@cloudflare/vitest-plugin` with real local D1/KV/R2 and migrations applied.
- Security properties get explicit tests (single-use tokens under concurrency, expiry, attempt limits, enumeration safety, CSRF, cookie flags, headers, IDOR on every route).
- E2E: Playwright, Chromium. Critical paths only.
- Milestone done = typecheck + lint + unit + relevant E2E all green, conventional commit, report, then stop and wait for `continue`.
